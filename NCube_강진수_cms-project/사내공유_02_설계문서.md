## 1. 아키텍처 개요

### 1.1 시스템 컨텍스트
```
┌──────────────────┐     ┌──────────────────┐
│   Admin Panel    │     │  Public Frontend │
│  (React + Vite)  │     │  (Next.js / SPA) │
└────────┬─────────┘     └────────┬─────────┘
         │  Admin API             │  Public API
         │  (JWT Bearer)          │  (API Key)
         ▼                        ▼
    ┌────────────────────────────────────┐
    │       NestJS Backend (REST)        │
    │  ┌──────────────────────────────┐  │
    │  │ ContentForm / Content        │  │
    │  │ Media / User / Role          │  │
    │  │ Webhook / AuditLog / ...     │  │
    │  └──────────────────────────────┘  │
    └──┬──────────┬───────────┬──────────┘
       │          │           │
       ▼          ▼           ▼
   PostgreSQL  MeiliSearch  File Storage
```

### 1.2 레이어 구분
| 레이어 | 역할 |
|---|---|
| **Admin API** | JWT 인증. 어드민 패널 전용. 모든 관리·운영 기능 |
| **Public API** | API 키 인증. 외부 프론트엔드용. 발행된 콘텐츠만 노출 |
| **Member API** | JWT (회원 토큰). 공개 사이트 회원 기능 |

## 4. 데이터 모델

### 4.1 핵심 엔티티 관계
```
User ─┐                                    ┌─ ContentForm ──┐
      ├─ UserRole ─ Role                   │                │
      └─ RefreshToken                      │                ▼
                                           │            Content ─ ContentVersion
FormCategory ──── 1:N ─────────────────────┘                │
                                                            ├─ Comment
Media ─ MediaFolder                                         └─ WorkflowAction

Webhook · ApiKey · AuditLog · Notification · Setting (독립)
Page · PageTemplate (페이지 빌더 — Business 에디션 대비)
```

### 4.2 주요 테이블
| 테이블 | 핵심 필드 | 비고 |
|---|---|---|
| `users` | type (ADMIN/MEMBER), isEmailVerified | 어드민과 공개 회원 통합 |
| `roles` | permissions (JSON 배열) | 권한 문자열 배열로 저장 |
| `user_roles` | status (PENDING/ACTIVE/REJECTED) | 역할 승인 워크플로우 |
| `content_forms` | fields (JSON), options (JSON) | 동적 필드 정의 |
| `form_categories` | order | 사이드바 정렬 순서 |
| `contents` | data (JSON), status, scheduledAt, viewCount, isPinned, isPrivate, inquiryStatus | 동적 데이터 + 게시판 확장 필드 |
| `content_versions` | version, data | 콘텐츠 히스토리 |
| `media` | thumbnails (JSON: sm/md/lg/webp) | 자동 생성된 변형 |
| `audit_logs` | action, entity, oldData, newData | 모든 액션 추적 |
| `api_keys` | keyHash (bcrypt), keyPrefix, permissions | Public API 접근 |
| `webhooks` | events (JSON 배열), secret | 이벤트 구독 |

### 4.3 동적 필드 설계
`ContentForm.fields`는 다음 구조의 JSON 배열:
```jsonc
[
  { "key": "title",     "type": "text",       "label": "제목",   "required": true },
  { "key": "content",   "type": "richtext",   "label": "본문",   "required": true },
  { "key": "thumbnail", "type": "image",      "label": "썸네일", "required": false },
  { "key": "isPinned",  "type": "boolean",    "label": "상단고정" }
]
```
`Content.data`는 위 정의를 따르는 동적 JSON. **Import 시 백엔드가 폼 스키마와 검증** (이번 스프린트 강화).

## 5. 모듈 설계 원칙

### 5.1 NestJS 모듈 구조
모든 기능은 다음 3요소로 구성:
```
Module (등록) → Controller (HTTP) → Service (비즈니스)
              ↓
            DTO (검증)  Guard (인증/인가)  Decorator (메타)
```

### 5.2 인증/인가
- **JwtAuthGuard**: 어드민 API의 기본 가드
- **PermissionsGuard + @Permissions(...)**: 메서드 단위 권한 체크
- **ApiKeyGuard**: Public API용 — `X-API-Key` 헤더 검증
- **PermissionsGuard 동작**: 사용자의 활성 Role들의 permissions를 모아 메서드 데코레이터와 매칭

### 5.3 인터셉터 / 필터
- **AuditLogInterceptor**: CRUD 액션을 자동 기록
- **HttpExceptionFilter**: 일관된 에러 응답 포맷

### 5.4 비동기 처리
- **이미지 변형**: 업로드 응답 즉시 반환, Sharp 처리는 비동기
- **예약 발행**: `@Cron('* * * * *')` 매분 체크
- **Webhook 재시도**: 실패 시 지수 백오프

## 6. API 구조

### 6.1 엔드포인트 분류 (약 100개)
| 그룹 | 경로 prefix | 인증 |
|---|---|---|
| 인증 | `/auth/*` | 없음 (로그인) / JWT |
| 사용자/역할 | `/users`, `/roles`, `/user-roles` | JWT + Permission |
| 콘텐츠 폼 | `/content-forms`, `/form-categories` | JWT + Permission |
| 콘텐츠 | `/contents` | JWT + Permission |
| 미디어 | `/media`, `/media/folders` | JWT + Permission |
| 검색 | `/search` | JWT |
| 운영 | `/audit-logs`, `/webhooks`, `/backups`, `/settings`, `/notifications` | JWT + Permission |
| Import/Export | `/import-export/*` | JWT + Permission |
| API 키 | `/api-keys` | JWT (관리자) |
| **Public API** | `/public/*` | **API Key** |
| **Member API** | `/public/auth/*`, `/public/member/*` | Member JWT |

### 6.2 Swagger
- `main.ts`에서 `SwaggerModule.setup()` 으로 자동 문서화
- 어드민 내 **API 가이드** 페이지가 Swagger JSON을 파싱해 cURL 복사 UI 제공

## 7. 동적 스키마 & Import 검증

### 7.1 Import 흐름
```
[파일 업로드] → [파싱: JSON/CSV]
      ↓
[Preview API] — 대상 ContentForm의 fields와 매칭 검증
      ↓
   결과: valid / invalid (어떤 필드가 누락/잉여인지 표시)
      ↓
[Execute API] — valid한 경우에만 일괄 insert
```

### 7.2 검증 규칙 (이번 스프린트 강화)
- 대상 폼에 정의되지 않은 키가 있으면 거부
- 필수 필드 누락 시 거부
- 타입 불일치 (예: number 필드에 string) 거부

## 8. 보안 설계

| 항목 | 구현 |
|---|---|
| 비밀번호 | bcrypt 해시 |
| JWT | Access(15분) + Refresh(7일). Refresh는 DB 저장 |
| API 키 | 노출은 발급 시 1회만. DB에는 bcrypt 해시 저장. prefix(8자)로 식별 |
| Rate Limit | `@nestjs/throttler` 글로벌 + 민감 엔드포인트 강화 |
| XSS | TipTap 본문 저장 시 DOMPurify Sanitize |
| 권한 우회 방지 | UI 메뉴 숨김 + API 가드 이중 체크 |
| 감사 로그 | 모든 CREATE/UPDATE/DELETE/LOGIN 기록 |
| 파일 업로드 | MIME 화이트리스트, 사이즈 제한, 확장자 검증 |

## 9. 환경 설정

### 9.1 필수 환경변수 (`backend/.env`)
| 키 | 설명 |
|---|---|
| `PORT` | 서버 포트 (예: 3000) |
| `NODE_ENV` | `development` / `production` |
| `DATABASE_URL` | PostgreSQL 연결 문자열 |
| `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET` | JWT 서명 키 |
| `JWT_ACCESS_EXPIRES_IN`, `JWT_REFRESH_EXPIRES_IN` | 만료 시간 (예: `15m`, `7d`) |
| `UPLOAD_PATH` | 파일 저장 경로 (예: `./uploads`) |
| `MAX_FILE_SIZE` | 업로드 최대 크기 (bytes) |
| `ADMIN_URL`, `PUBLIC_URL` | CORS 허용 오리진 |

> `env.validation.ts`에서 class-validator로 부팅 시 검증. 누락 시 즉시 에러.

### 9.2 자동화된 부팅 시퀀스 (`npm run dev`)
1. `prisma generate` — Prisma Client 생성
2. `node scripts/setup-db.js` — DB 존재 여부 확인 → 없으면 생성 + 마이그레이션
3. `nest start --watch` — 서버 기동 (변경 감지)

## 11. 운영 / 배포 고려사항

- **마이그레이션**: `prisma migrate deploy`로 운영 환경에 적용
- **백업**: 어드민 UI에서 DB + 파일 통합 ZIP 다운로드. 복원 API 제공
- **모니터링**: 감사 로그 + Webhook으로 외부 알림 시스템 연동 가능
- **무중단 배포**: NestJS 인스턴스 다중 기동 + 로드밸런서 (이후 단계)
