## 0. 빠른 시작 (TL;DR)

```bash
# 1. 저장소 클론
git clone <repo> && cd cms-project

# 2. pnpm 설치
npm install -g pnpm
pnpm install

# 3. .env 작성 (backend/.env)
#    DATABASE_URL, JWT_* 등 필수값 채우기

# 4. PostgreSQL 기동 후
cd backend
npm run dev      # prisma generate + DB 자동 생성 + 서버 시작

# 5. 어드민 패널 기동 (다른 터미널)
cd frontend/admin
pnpm dev
```

기본 어드민 계정 (시드 기준): `admin@cms.com` / `admin123`

## 1. 설치 및 실행

### 1.1 사전 요구사항
| 항목 | 버전 |
|---|---|
| Node.js | 20+ (24까지 검증) |
| pnpm | 9+ |
| PostgreSQL | 14+ |
| (선택) MeiliSearch | 검색 기능 활성화 시 |

### 1.2 설치 절차

#### Step 1. 의존성 설치
프로젝트 루트에서:
```bash
pnpm install
```
> **참고**: `npm install`로도 동작하지만, lockfile 일관성을 위해 pnpm 권장.

#### Step 2. 환경 변수 설정
`backend/.env` 파일 생성:
```env
PORT=3000
NODE_ENV=development
DATABASE_URL=postgresql://USER:PASS@localhost:5432/cms_db
JWT_ACCESS_SECRET=change-me-please
JWT_ACCESS_EXPIRES_IN=15m
JWT_REFRESH_SECRET=change-me-too
JWT_REFRESH_EXPIRES_IN=7d
UPLOAD_PATH=./uploads
MAX_FILE_SIZE=10485760
ADMIN_URL=http://localhost:5173
PUBLIC_URL=http://localhost:3001
```

#### Step 3. 백엔드 실행
```bash
cd backend
npm run dev
```
이 명령은 자동으로:
1. Prisma Client 생성
2. DB 존재 확인 → 없으면 **자동 생성 + 마이그레이션**
3. 서버 시작 (변경 감지 모드)

#### Step 4. 어드민 패널 실행
```bash
cd frontend/admin
pnpm dev
```
브라우저에서 `http://localhost:5173` 접속.

### 1.3 트러블슈팅

| 증상 | 원인 / 해결 |
|---|---|
| `Property 'xxx' does not exist on type 'PrismaService'` 등 252개 에러 | Prisma Client 미생성 → `npx prisma generate` |
| `Database "cms_db" does not exist` | DB 미생성 → `npm run dev`가 자동 처리하거나 수동으로 `createdb cms_db` |
| `ECONNREFUSED` | PostgreSQL 미기동 → 서비스 시작 또는 Docker 컨테이너 확인 |
| `An instance of EnvironmentVariables has failed the validation` | `.env` 누락 또는 값 누락 → 위 Step 2 참고 |
| 윈도우에서 `rm -rf` 안 됨 | `rmdir /s /q node_modules` 또는 Git Bash 사용 |

## 3. 핵심 기능 사용 흐름

### 3.1 콘텐츠 폼 만들기

> "빈 도화지" 컨셉의 출발점. 코드 변경 없이 콘텐츠 구조를 정의합니다.

1. **사이드바 > 콘텐츠 관리** 클릭 → 콘텐츠 관리 허브 진입
2. **콘텐츠 폼 > 콘텐츠 폼 추가**
3. 기본 정보 입력
   - **이름**: 예) `공지사항`
   - **고유 주소(slug)**: 예) `notice`  (API 경로에 사용)
   - **카테고리**: (선택) 사이드바에서 묶일 그룹
4. **입력 항목 추가**
   - `title` — 텍스트 / 필수
   - `content` — 텍스트 에디터 / 필수
   - `thumbnail` — 이미지 / 선택
   - `isPinned` — 예/아니오 / 선택
5. **생성** 클릭 → 목록에 추가됨

### 3.2 카테고리로 그룹핑

1. **콘텐츠 관리 > 카테고리**
2. **카테고리 추가** — 이름, 순서 지정
3. 콘텐츠 폼 수정 화면에서 카테고리 선택
4. 사이드바 "콘텐츠" 그룹이 카테고리별로 자동 분리됨

> 카테고리를 삭제해도 소속된 폼은 사라지지 않고 "카테고리 없음" 그룹으로 자동 이동.

### 3.3 콘텐츠 작성과 발행

1. **사이드바 > 콘텐츠 > 공지사항** 진입
2. **글 추가** 클릭
3. 필드 입력 (콘텐츠 폼 정의를 그대로 따름)
4. 발행 옵션
   - **즉시 발행**: 발행 버튼 클릭
   - **초안 저장**: 저장만 — 외부에 노출되지 않음
   - **예약 발행**: 상태를 `예약`으로, 발행 시각 지정 → 백엔드 크론이 매분 체크 후 자동 발행
5. 발행 후 목록에서 상태 배지 확인 (DRAFT / PUBLISHED / SCHEDULED / ARCHIVED)

#### 버전 관리
- 콘텐츠를 수정할 때마다 `ContentVersion`이 자동 저장
- 상세 화면 > 버전 이력 > **복원** 가능

#### 휴지통 (Soft Delete)
- 삭제 시 즉시 영구삭제 X. `deletedAt` 표시
- 복원 또는 영구 삭제 가능

### 3.4 미디어 업로드

1. **사이드바 > 파일 관리**
2. 파일 드래그앤드롭 또는 **업로드** 버튼
3. 업로드 즉시 백엔드가 비동기 처리
   - 원본 + sm / md / lg / WebP 변형 자동 생성
4. 폴더 트리로 정리 가능 (드래그앤드롭)
5. 파일 선택 → 메타데이터(대체 텍스트, 캡션) 편집

### 3.5 사용자와 역할

#### 사용자 등록
1. **사용자/권한 > 사용자**
2. **사용자 추가** — 이름, 이메일, 비밀번호, 사용자 타입 (ADMIN/MEMBER)

#### 역할 부여
1. **사용자/권한 > 역할**
2. 역할 만들기 (예: `편집자`, `뷰어`)
3. 권한 체크박스로 선택 (예: `content:read`, `content:write`)
4. **사용자 > 역할 할당** — 해당 사용자에게 역할 부여

> 권한이 다른 사용자는 사이드바 자체가 다르게 보입니다. API 레벨에서도 이중 체크 (403).

### 3.6 실시간 알림

- 다른 관리자가 콘텐츠를 발행/수정/삭제하면 헤더의 **🔔 알림 벨**에 즉시 표시
- 클릭 시 알림 목록, 읽음 처리, 일괄 삭제 가능
- WebSocket 기반 — 새로고침 불필요

### 3.7 검색

1. 상단 검색바에 키워드 입력
2. MeiliSearch가 한국어 형태소 기반으로 검색
3. 검색 결과는 콘텐츠 폼별로 분류 표시

> 인덱스가 깨졌을 경우 **시스템 설정 > 검색 인덱스 재구축** 실행.

### 3.8 Import / Export

#### Export
1. **운영/데이터 > Import/Export**
2. **내보내기** 섹션 — 대상 콘텐츠 폼 선택
3. **JSON 다운로드** 또는 **CSV 다운로드**

#### Import
1. **가져오기** 섹션 — 파일 업로드
2. 대상 콘텐츠 폼 선택
3. **미리보기** — 백엔드가 스키마 검증 결과 표시
   - ✅ valid: 모든 필드 매칭 성공
   - ❌ invalid: 어떤 필드가 누락/잉여인지 표시
4. valid한 경우에만 **실행** 버튼 활성화

> Import는 **대상 폼의 스키마를 위반하면 차단**됩니다. 잘못된 데이터 유입 방지.

### 3.9 Webhook

1. **운영/데이터 > Webhook**
2. **Webhook 추가**
   - 이름, URL (예: Slack incoming webhook URL)
   - 구독 이벤트 (`content.published`, `content.deleted` 등)
   - Secret (선택, 서명 검증용)
3. 이벤트 발생 시 자동 POST. 실패 시 재시도.

### 3.10 백업 / 복원

#### 백업 생성
1. **운영/데이터 > 백업/복원**
2. **백업 생성** 클릭 → DB + 업로드 파일 ZIP 생성
3. 목록에서 다운로드

#### 백업 복원
1. ZIP 파일 업로드 또는 기존 백업 선택
2. **복원** 클릭 → 확인 후 실행

> 운영 환경에서는 복원 전 별도 환경에서 리허설 권장.

### 3.11 API 키 발급 (외부 통합용)

1. **시스템 설정 > API 키**
2. **새 키 발급** — 이름, 권한, 만료일 설정
3. 발급 직후 **단 1회만** 평문 표시 → 안전한 곳에 보관
4. 외부 앱에서 헤더 `X-API-Key: sk_live_xxxx...` 로 호출

### 3.12 감사 로그

- **운영/데이터 > 감사 로그**
- 모든 CREATE/UPDATE/DELETE/LOGIN 추적
- 사용자/액션/엔티티/기간 필터링
- 변경 내역(oldData → newData) 확인 가능

## 4. Public API 사용법 (외부 개발자)

### 4.1 인증
모든 Public API 호출 시 헤더에 API 키 포함:
```
X-API-Key: sk_live_xxxxxxxxxxxxx
```

### 4.2 주요 엔드포인트
| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/public/content-forms` | 콘텐츠 폼 목록 |
| GET | `/public/content-forms/:slug` | 폼 상세 |
| GET | `/public/contents/:contentFormSlug` | 폼별 콘텐츠 목록 (발행됨만) |
| GET | `/public/contents/:contentFormSlug/:slug` | 콘텐츠 상세 |

### 4.3 예시
```bash
curl -H "X-API-Key: sk_live_xxx" \
  https://api.example.com/public/contents/notice
```

응답:
```json
{
  "data": [
    {
      "id": "clx...",
      "title": "서비스 점검 안내",
      "data": { "content": "...", "isPinned": false },
      "publishedAt": "2026-04-21T15:00:00Z"
    }
  ],
  "meta": { "total": 12, "page": 1 }
}
```

### 4.4 API 가이드 페이지
어드민에서 **API 가이드** 메뉴 진입 → 엔드포인트별 cURL 복사·테스트 가능. Swagger 자동 문서화.

## 5. 회원 기능 (Public Site)

### 5.1 회원 가입 / 로그인
```bash
POST /public/auth/register    # 가입
POST /public/auth/login       # 로그인 → Access/Refresh 토큰 발급
POST /public/auth/verify-email
POST /public/auth/forgot-password
POST /public/auth/reset-password
```

### 5.2 회원 글 작성 / 수정
```bash
POST   /public/member/contents/:contentFormSlug   # 글 작성
PATCH  /public/member/contents/:id                # 자기 글 수정
DELETE /public/member/contents/:id                # 자기 글 삭제
GET    /public/member/contents/my                 # 내 글 목록
POST   /public/member/media/upload                # 파일 업로드
```

> 회원이 작성할 수 있는 콘텐츠 폼은 어드민에서 설정.

## 6. 자주 묻는 질문 (FAQ)

**Q. 콘텐츠 폼을 만들면 DB 테이블이 새로 생기나요?**
A. 아니요. JSONB 필드에 동적으로 저장됩니다. 마이그레이션 불필요.

**Q. 발행한 콘텐츠를 외부 사이트에서 어떻게 가져오나요?**
A. API 키를 발급받아 Public API(`/public/contents/...`)를 호출하세요.

**Q. 백업 복원 시 기존 데이터는?**
A. 복원하면 현재 DB가 백업 시점으로 덮어쓰기됩니다. 사전 백업 권장.

**Q. 다국어 콘텐츠는?**
A. Starter는 한국어 우선. 다국어는 Business 에디션에서 제공 예정.

**Q. 페이지 빌더(드래그앤드롭으로 페이지 만들기)는?**
A. Business 에디션에서 제공. Starter는 헤드리스 API 중심.

**Q. 운영 중 npm run dev가 매번 prisma generate를 도는데 느려지지 않나요?**
A. 이미 생성된 상태에서는 ~200ms 정도로 빠르게 통과합니다.

## 7. 권한 목록 (역할 설정 시 참고)

| 권한 키 | 설명 |
|---|---|
| `content:read` | 콘텐츠 조회 |
| `content:write` | 콘텐츠 작성/수정 |
| `content:delete` | 콘텐츠 삭제 |
| `content:publish` | 콘텐츠 발행 |
| `form:manage` | 콘텐츠 폼 관리 |
| `media:manage` | 미디어 관리 |
| `user:manage` | 사용자 관리 |
| `role:manage` | 역할/권한 관리 |
| `settings:manage` | 시스템 설정 |
| `backup:manage` | 백업/복원 |
| `webhook:manage` | Webhook 관리 |
| `apikey:manage` | API 키 관리 |
| `audit:read` | 감사 로그 조회 |

> 권한 키는 운영 중 추가 가능. 자세한 매트릭스는 `role/decorators/permissions.decorator.ts` 참고.
