# Starter CMS — 기획문서

작성일: 2026-04-21
버전: 1.0 (Starter 에디션 완성 기준)

---

## 1. 프로젝트 개요

### 1.1 프로젝트명
**Starter CMS** — 빈 도화지에서 시작하는 확장형 헤드리스 CMS 플랫폼

### 1.2 한 줄 요약
사내 SI 프로젝트에서 반복되던 어드민/CMS 구축 작업을 **공통 플랫폼**으로 통합하여, 신규 고객사 투입 시 기본 구축 공수를 대폭 절감하는 **헤드리스 CMS**.

### 1.3 핵심 컨셉
- **빈 도화지(Blank Canvas)**: 사전 정의된 콘텐츠 스키마 없이, 고객사가 직접 콘텐츠 폼을 설계
- **헤드리스(Headless)**: 백엔드(API)와 프론트엔드(렌더링)를 완전히 분리 → 어떤 채널이든 연동 가능
- **점진적 확장(Progressive Editions)**: Starter → Business → Enterprise → Professional 순으로 점진 승급

## 2. 배경과 문제 정의

### 2.1 기존 SI 모델의 문제
| 항목 | 현황 |
|---|---|
| 반복 작업 | 고객사마다 로그인 / 권한 / 게시판 / 미디어 / 감사로그를 매번 처음부터 개발 |
| 품질 편차 | 매번 개발자가 달라 코드 품질·보안 수준이 일관되지 않음 |
| 유지보수 부담 | 프로젝트별로 코드베이스가 갈라져 유지보수 비용이 누적됨 |
| 납기 압박 | 기본 구축에 시간이 소모되어 고객 핵심 요구에 집중할 여력이 줄어듦 |

### 2.2 해결 방향
> **공통 CMS 플랫폼을 한 번 제대로 만들어두고, 고객 요구는 에디션/확장 모듈로 대응한다.**

- 콘텐츠 구조 자체를 사용자가 정의(JSON 필드 기반 동적 스키마)
- 운영 필수 기능(감사로그, 알림, 백업, Webhook 등)은 기본 탑재
- 외부 프론트엔드는 API/Public API로 연결 → 멀티 채널 대응

## 3. 프로젝트 목적과 KPI

### 3.1 목적
1. **재사용 가능한 공통 기반 확보** — 매번 다시 만들지 않음
2. **고객 맞춤 확장성** — 에디션/모듈 단위 조합으로 대응
3. **헤드리스 구조** — 웹, 앱, 키오스크, IoT 등 멀티 채널 배포

### 3.2 성공 지표
- 신규 SI 투입 시 기본 구축 공수 **50% 이상 절감**
- Starter 기준 **POC 1주일 내 배포 가능**
- 16개 핵심 기능 / 100개 이상 API 자동 문서화

## 4. 제품 구조 — 에디션 전략

| 에디션 | 대상 고객 | 제공 범위 | 진행 현황 |
|---|---|---|---|
| **Starter** | 개발팀 보유 기업 / 헤드리스 필요 고객 | API + Admin Panel | ✅ 완성 |
| **Business** | 비개발자 콘텐츠 운영자 보유 고객 | Starter + 페이지 빌더 + 다국어 + SEO | 🟡 다음 스프린트 착수 |
| **Enterprise** | 대기업 / 멀티 브랜드 | Business + 멀티사이트 + SSO + 승인 워크플로우 | 🔴 후속 단계 |
| **Professional** | 특수 요구 고객 | 모든 에디션 + 맞춤형 모듈 개발 | 🔄 상시 (수주 단위) |

> 점진적 확장: Starter로 시작한 고객도 추후 Business/Enterprise로 승급 가능.

## 5. Starter 에디션 — 기능 명세

### 5.1 콘텐츠 관리 (7개)
| # | 기능 | 설명 |
|---|---|---|
| 1 | 콘텐츠 폼 CRUD | JSON 필드 기반 동적 스키마. 텍스트/숫자/이미지/리치텍스트/예-아니오 등 필드 타입 지원 |
| 2 | 폼 카테고리 | 콘텐츠 폼을 카테고리로 묶어 사이드바 그룹핑. 삭제 시 소속 폼은 "카테고리 없음"으로 자동 이동 |
| 3 | 콘텐츠 CRUD + 버전 관리 | 발행/초안/검토/승인/반려/보관 상태. 버전 이력 자동 저장, 복원 가능 |
| 4 | 예약 발행 | 발행 시각 지정 → 크론 1분 단위 체크 자동 발행 |
| 5 | 휴지통 (Soft Delete) | 삭제 즉시 영구 삭제하지 않고 보관. 복원/영구삭제 가능 |
| 6 | Import / Export | JSON·CSV 양방향. **대상 폼 스키마 검증 강화** (이번 스프린트) |
| 7 | 검색 | MeiliSearch 기반 한국어 친화 전문검색. 인덱스 재구축 API 제공 |

### 5.2 운영 / 통합 (9개)
| # | 기능 | 설명 |
|---|---|---|
| 8 | 역할 기반 권한 | Role-Permission 매핑. UI/API 양쪽에서 권한 체크 |
| 9 | 미디어 관리 | 폴더 트리, 드래그앤드롭 업로드, 이미지 자동 최적화 (Sharp: 리사이즈/WebP/썸네일) |
| 10 | 실시간 알림 | WebSocket 기반. 다른 관리자 작업이 헤더 벨에 즉시 반영 |
| 11 | 감사 로그 | CREATE/UPDATE/DELETE/LOGIN 등 모든 주요 액션 기록. 필터 조회 |
| 12 | Webhook | Slack/Discord 호환 페이로드. 이벤트 구독 및 재시도 |
| 13 | 백업/복원 | DB + 파일 업로드 ZIP. 다운로드/업로드/복원 가능 |
| 14 | 시스템 설정 | 사이트명, 업로드 제한, 알림 정책 등 런타임 설정 |
| 15 | API 키 관리 | Public API 외부 통합용 키 발급/회수/만료 |
| 16 | 회원 인증 | Public 사이트 회원 가입/로그인/이메일 인증/비밀번호 재설정 |

### 5.3 부가 기능
- **API 가이드 페이지**: 어드민 내 Swagger 연동. 엔드포인트별 cURL 복사·테스트
- **대시보드**: 콘텐츠 통계, 최근 활동, 알림 요약

## 6. 사용자 / 페르소나

| 페르소나 | 역할 | 주요 사용 시나리오 |
|---|---|---|
| **시스템 관리자** | CMS 인스턴스 운영 책임 | 사용자/역할/시스템 설정, 백업, 감사 로그 모니터링 |
| **콘텐츠 편집자** | 일상 콘텐츠 작성·발행 | 콘텐츠 폼에 글 작성, 예약 발행, 미디어 업로드 |
| **검토자/승인자** | 발행 전 콘텐츠 검수 | 워크플로우 액션(승인/반려), 감사 로그 확인 |
| **외부 개발자** | Public API로 콘텐츠 소비 | API 키로 인증, REST 호출로 콘텐츠 조회 |
| **공개 사이트 회원** | Public 사이트 이용자 | 회원 가입/로그인, 콘텐츠 작성(허용 폼), 자기 글 관리 |

## 7. 핵심 사용자 시나리오

### 시나리오 A — 신규 고객사 POC (Starter)
1. 고객사 도메인에 Starter 배포 (1일)
2. 콘텐츠 폼 정의 (예: 공지사항, FAQ, 채용공고) — 코드 변경 없음
3. 운영자 계정 발급, 역할 부여
4. API 키 발급 → 고객사 프론트엔드 팀에 전달
5. 1주일 내 시범 운영 시작

### 시나리오 B — 일상 콘텐츠 운영
1. 편집자 로그인 → "공지사항" 폼 진입
2. 글 작성 (TipTap 리치텍스트 + 이미지 업로드)
3. 예약 발행 시각 설정 후 저장
4. 다른 관리자 화면에 알림 즉시 반영
5. 정해진 시각에 백엔드 크론이 자동 발행

### 시나리오 C — 외부 채널 연동
1. 외부 개발자가 어드민 "API 가이드"에서 cURL 복사
2. 본인 앱(Next.js/Flutter 등)에 API 키 세팅
3. `/public/contents/:slug` 호출로 콘텐츠 수신
4. Webhook 등록 → 발행 이벤트를 Slack 알림으로 받기

## 8. 비기능 요구사항

| 항목 | 요구사항 |
|---|---|
| 보안 | JWT 인증, API 키 bcrypt 해시 저장, Rate Limit, XSS Sanitize, 감사 로그 |
| 확장성 | 모듈식 NestJS 구조 → 에디션별 모듈 추가/제거 용이 |
| 성능 | 이미지 비동기 처리(Sharp), MeiliSearch로 검색 분리 |
| 가용성 | 백업/복원 기본 제공. 마이그레이션 자동화 (Prisma) |
| 다국어 | **Starter는 한국어 우선** — 다국어는 Business에서 제공 |
| 라이선스 | 모든 핵심 OSS가 MIT/Apache-2.0 → 상업적 제약 없음 |

## 9. 한계와 향후 로드맵

### 9.1 Starter의 한계
- **다국어(i18n) 미지원** → Business 에디션에서 제공
- **페이지 빌더 없음** → Business 에디션
- **실시간 미리보기 없음** → Business 에디션
- **대규모 트래픽 실전 검증 부족** → 안정화 단계에서 보강
- **E2E 자동화 테스트 커버리지 부족** → 수동 QA 중심, 자동화 확충 필요

### 9.2 로드맵
| 단계 | 시기 | 주요 내용 |
|---|---|---|
| Starter 안정화 | 진행 중 | 품질·성능·접근성·문서 정비 |
| Business 착수 | 다음 스프린트 | 페이지 빌더(Craft.js), 다국어, SEO |
| Enterprise | 이후 | 멀티사이트, SSO, 승인 워크플로우, 필드 레벨 권한 |
| Professional | 상시 | 고객 맞춤 모듈 |

## 10. 의사결정 기록 (주요)

- **NestJS 채택**: 모듈 시스템 / TypeScript 강제 / Swagger 자동 생성 → 엔터프라이즈 적합
- **Prisma + PostgreSQL JSONB**: 동적 스키마 표현. JSONB 인덱스 최적화 가능
- **MeiliSearch**: 한국어 검색 품질, 운영 단순함 (Elastic 대비)
- **헤드리스 우선**: 페이지 빌더 없이 시작 → 멀티 채널 대응을 1순위
- **에디션 분리 전략**: 모든 고객을 한 에디션으로 강요하지 않음. 점진 승급 가능
