# 시연 시나리오 (화면 공유 파트)

약 15분. 8개 시연 블록. 각 블록마다 **포인트**(청중에게 꼭 말할 것)와 **조작 순서**, **예상 소요**, **실패 시 대응**을 정리해뒀습니다.

## 사전 준비 (시연 시작 전 5분 전까지)

- [ ] 백엔드 서버 기동 (`cd backend && npm run start:dev`)
- [ ] 프론트 dev 서버 기동 (`cd frontend/admin && pnpm dev`)
- [ ] PostgreSQL 떠 있는지 확인 (`pg_isready`)
- [ ] admin 계정 로그인 가능한 상태 (`admin@cms.com` / `admin123`)
- [ ] 뷰어 계정 준비 (Role이 `뷰어`인 사용자) — 미리 로그아웃해둘 것
- [ ] 샘플 이미지 1장 준비 (드래그앤드롭 업로드용)
- [ ] Postman 또는 curl이 준비된 터미널 탭 열어두기
- [ ] 알림 시연용: **별도 브라우저 창/시크릿 모드**로 동일 계정 하나 더 로그인
- [ ] 브라우저 확대 125% 권장 (청중 가독성)
- [ ] 콘솔 / 개발자 도구는 **닫아둘 것** (깔끔한 화면)

## 블록 1 — 콘텐츠 폼 만들기 (2분)

**포인트**: "빈 도화지에서 시작해서 3분 만에 새로운 콘텐츠 타입이 생깁니다."

### 조작
1. 사이드바 **"콘텐츠 관리"** 클릭 → 허브 레이아웃 전환 (⚡ 작업 맥락 분리 강조)
2. **콘텐츠 폼 > 콘텐츠 폼 추가**
3. 이름: `공지사항`, 고유주소: `notice`
4. 입력 항목 추가:
   - `title` (텍스트, 필수)
   - `content` (텍스트 에디터, 필수)
   - `isPinned` (예/아니오, 선택)
   - `thumbnail` (이미지, 선택)
5. **생성** 클릭
6. 목록에 `공지사항` 추가된 것 확인

### 말하기
> "여기서 중요한 건 이게 **데이터베이스 테이블을 새로 만드는 게 아니라는** 점입니다. JSON 필드로 동적으로 관리되기 때문에, **고객사에서 직접 스키마를 설계**할 수 있어요. 개발자 개입 없이요."

### 실패 시
- 저장 실패: F12 네트워크 탭 → 500 에러면 "잠깐 에러가 났네요" 하고 다음 블록으로. DB/서버 상태는 시연 후 점검.

## 블록 2 — 카테고리와 사이드바 그룹핑 (2분)

**포인트**: "콘텐츠 폼이 많아지면 관리가 어려워지죠. 카테고리로 묶을 수 있습니다."

### 조작
1. **카테고리** 메뉴 진입
2. 새 카테고리 2개 생성:
   - `운영 공지` (순서 0)
   - `사용자 참여` (순서 1)
3. 콘텐츠 폼 목록 → 방금 만든 `공지사항` 수정 → 카테고리를 **운영 공지**로 지정
4. 이미 있던 `자유게시판`(또는 아무 폼) → **사용자 참여**로 지정
5. **사이드바의 "콘텐츠" 그룹 펼치기** → 카테고리별로 서브그룹이 만들어진 것 확인
6. 서브그룹 헤더 클릭해서 접기/펼치기 시연 (부드러운 애니메이션)

### 말하기
> "카테고리 순서는 **사이드바 정렬에 즉시 반영**됩니다. 그리고 카테고리를 지우더라도, 소속된 콘텐츠 폼은 사라지지 않고 '카테고리 없음'으로 자동 이동합니다. 데이터 안전장치죠."

## 블록 3 — 콘텐츠 작성 + 예약 발행 (2분)

**포인트**: "실제 편집자가 어떻게 콘텐츠를 작성하고 예약 발행하는지 보여드립니다."

### 조작
1. 사이드바 **콘텐츠 > 공지사항** 클릭
2. **글 추가** 버튼
3. 제목: `서비스 점검 안내`
4. 본문: 리치 텍스트 에디터(TipTap)에서 **볼드/이탤릭/리스트** 시연
5. 썸네일에 이미지 업로드 (미디어 피커 사용)
6. **발행** 클릭 → 즉시 발행

### 추가 (예약 발행)
7. 새 글 하나 더 — `다음 이벤트 안내`
8. 상태를 **예약**으로, 시간을 **지금으로부터 2분 후** 지정
9. 저장 → 목록에 "예약됨" 배지 표시 확인

### 말하기
> "예약 발행은 백엔드 크론이 1분마다 체크해서 자동 발행합니다. 퇴근 시간에 예약 걸어두고 나가시면 됩니다."

## 블록 4 — 미디어 업로드 + 이미지 자동 최적화 (1.5분)

**포인트**: "이미지 업로드하면 백엔드가 자동으로 리사이즈/WebP 변환/썸네일 생성까지 해줍니다."

### 조작
1. 사이드바 **파일 관리**
2. 준비한 샘플 이미지 드래그앤드롭
3. 업로드 완료 후 해당 파일 상세 진입
4. **원본 / sm / md / lg / webp** 버전이 자동 생성된 것 확인
5. 폴더 하나 만들고(`공지 이미지`) 파일 이동 시연

### 말하기
> "Sharp 라이브러리를 써서 업로드 즉시 비동기로 처리합니다. 사용자는 기다릴 필요 없이 바로 다음 작업 진행 가능해요."

## 블록 5 — 역할 / 권한 시연 (2분) ⭐ 핵심

**포인트**: "권한이 다른 사용자에게는 UI 자체가 다르게 보입니다."

### 조작
1. 현재 로그인된 admin 계정의 **사이드바 전체** 한 번 보여주기 (모든 메뉴 다 보임)
2. 우상단 또는 사이드바 하단에서 **로그아웃**
3. 뷰어 계정으로 로그인
4. 사이드바 비교:
   - "콘텐츠 관리" 메뉴는 보임 (읽기 권한 있음)
   - "사용자/권한", "시스템 설정", "운영/데이터" 등은 **숨김**
5. 콘텐츠 폼 목록 진입 → **목록은 보이지만 "추가/수정/삭제" 버튼이 없음**
6. URL로 `/content-forms/xxx/edit` 직접 입력 → **접근 권한 없음 토스트 + 대시보드 리다이렉트**

### 말하기
> "핵심은 **백엔드와 프론트엔드 양쪽에서 권한을 체크**한다는 거예요. UI에서 버튼을 숨기는 건 UX 차원이고, 백엔드는 API 레벨에서 다시 한 번 403으로 막습니다. 우회 불가능해요."

### 다시 admin으로 복귀
- 로그아웃 → admin 재로그인

## 블록 6 — API 가이드 + 외부 API 호출 (2분) ⭐ 핵심

**포인트**: "헤드리스 CMS의 핵심 — 외부 프론트엔드가 API로 접근하는 경험을 보여드립니다."

### 조작
1. **API 가이드** 페이지 진입
2. 좌측 네비에서 **"콘텐츠 폼 (ContentForm)"** 섹션 → `GET /content-forms` 확인
3. **"Public API"** 섹션 → `GET /public/content-forms/:slug` 확인
4. cURL 복사 버튼 클릭 → 미리 열어둔 **터미널에 붙여넣고 실제 실행**
5. JSON 응답이 뜨는 것 확인 (청중에게 2초 보여주기)
6. 이번엔 **"콘텐츠"** 섹션의 `GET /public/contents/notice` 실행 → 방금 만든 공지사항이 JSON으로 나옴

### 말하기
> "이 응답을 그대로 Next.js, Flutter, 심지어 키오스크에서도 가져다 쓸 수 있습니다. 이게 **헤드리스의 본질**이에요."

### 실패 시
- 인증 에러: API 키가 없으면 401. 미리 한 번 테스트해두고, 시연 땐 복사해둔 cURL 사용. 준비 부족 시 "이 부분은 실행 결과를 스크린샷으로 보여드릴게요" 하며 넘어가기.

## 블록 7 — 실시간 알림 (1.5분)

**포인트**: "WebSocket으로 다른 관리자의 작업이 즉시 표시됩니다."

### 조작 — 준비: 별도 브라우저(또는 시크릿 창)에 admin 한 번 더 로그인
1. 메인 창과 보조 창을 좌우로 나란히 배치
2. **보조 창에서** 콘텐츠 하나를 만들거나 수정 → 발행
3. **메인 창의 헤더 알림 벨에 빨간 뱃지가 즉시 올라오는 것** 확인
4. 알림 벨 클릭 → 최근 알림 목록 확인

### 말하기
> "이렇게 팀 협업 중인 상황에서 다른 사람의 변경사항을 놓치지 않게 해줍니다. 그리고 알림은 **사용자 역할 기반**으로 필터링돼요. 예를 들어 편집자는 '콘텐츠 생성' 알림만 받고, 감사자는 '삭제' 알림만 받게 설정할 수 있어요."

## 블록 8 — Import / Export + 백업 (2분)

**포인트**: "대량 데이터도 다루고, 재해 복구도 됩니다."

### 조작 (Export)
1. 사이드바 **Import/Export**
2. **내보내기** 섹션에서 `공지사항` 선택 → JSON 다운로드
3. 다운받은 파일 에디터로 열어서 구조 간단히 보여주기 (메타 + data 배열)

### 조작 (Import 검증)
4. **가져오기** 섹션에서 파일 업로드 → `공지사항` 선택 → 미리보기 → **valid** 표시
5. 이번에는 **다른 폼**(예: `자유게시판`) 선택해서 같은 파일 import 시도
6. **"대상 콘텐츠 폼에 정의되지 않은 필드가 포함되어 있습니다"** 에러 표시 확인

### 말하기
> "여기서 중요한 점은, 잘못된 폼에 데이터가 섞이지 않도록 **백엔드가 스키마를 검증**한다는 겁니다. 이번 주에 바로 강화한 부분이에요."

### 조작 (백업 — 시간 남을 때만)
7. 운영/데이터 > **백업/복원** 진입 (루트 허브로 자동 전환)
8. **백업 생성** 버튼 → DB + 파일 업로드 ZIP 생성
9. 목록에 백업 파일 추가된 것 확인, 다운로드 가능

### 말하기
> "배포 전후 스냅샷을 남겨두거나, 마이그레이션 리허설 용도로 씁니다."
